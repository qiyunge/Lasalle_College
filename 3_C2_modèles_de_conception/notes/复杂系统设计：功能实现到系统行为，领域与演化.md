# 复杂系统设计：从功能实现到行为、领域与演化

## 1. 复杂系统设计不再只是“实现功能”

传统软件开发中，人们往往认为：

> 系统设计的目标，是实现需求。

例如：

- 用户注册
- 下订单
- 编辑文本
- AI correction
- 查看统计

这种思维本质上是：

# 功能驱动（Function-Driven）

系统被看作：

> 一组功能模块的集合。

因此：

早期软件工程大量使用：

- Use Case
- CRUD
- Functional decomposition

来分析系统。

---

但是：

随着系统规模增长，

人们逐渐发现：

> 系统真正困难的地方，
> 并不在“功能是否存在”，
> 而在于：
>
> - 系统行为（behavior）
> - 状态变化（state transition）
> - 领域语义（domain semantics）
> - 交互复杂性（interaction complexity）
> - 约束（constraints）
> - 不确定性（uncertainty）
> - 演化（evolution）

因此：

现代复杂系统设计，
已经逐渐从：

# “功能实现”
转向：
# “复杂行为系统设计”。

---

# 2. 从业务功能出发（Business-Driven Design）

复杂系统通常仍然从：

# 业务功能

开始。

因为：

系统首先必须解决现实问题。

例如：

语言学习系统：

- 写作
- correction
- vocabulary review
- progress tracking

电商系统：

- 下单
- 支付
- 发货
- 库存管理

因此：

Use Case 仍然重要。

它帮助系统回答：

> “系统对用户提供什么能力？”

---

但是：

Use Case 只能描述：

# 外部行为（external interaction）

而无法描述：

- 内部状态
- 复杂规则
- 长期演化
- distributed interaction
- failure handling

因此：

复杂系统需要更多建模层次。

---

# 3. 领域驱动设计（Domain-Driven Design）

随着系统复杂度提高，

开发者逐渐发现：

> 真正困难的，
> 不是“写代码”，
> 而是：
>
> “理解领域”。

例如：

一个 scheduling system：

真正复杂的是：

- task dependency
- resource constraints
- release time
- dispatch policy
- machine state
- event semantics

而不是：

“写一个 API”。

因此：

现代复杂系统越来越强调：

# Domain Modeling。

---

## DDD 的核心思想

系统应该围绕：

# 领域语义（domain semantics）

而不是：

# UI 或 database schema

来设计。

---

例如：

在 scheduling system 中：

真正核心对象可能是：

- Task
- Machine
- Event
- SchedulerState
- DispatchPolicy

而不是：

- 页面
- 表单
- CRUD API

---

DDD 强调：

## Bounded Context

复杂系统必须：

# 拆分语义边界。

因为：

不同模块：

可能对同一个概念有不同理解。

---

例如：

“Task”：

在：

- Scheduling Context
- Billing Context
- Monitoring Context

中的含义可能不同。

---

# 4. Event-Driven Design（事件驱动）

现代复杂系统越来越：

# event-driven。

因为：

现实世界本质上是：

# continuously evolving events。

---

传统系统：

通常是：

input → process → output。

而现代系统：

更多是：

event → reaction → new events。

---

例如：

在 scheduling system 中：

- TaskReleased
- TaskStarted
- TaskCompleted
- MachineFailed

这些事件：

会触发：

- state transition
- downstream logic
- notifications
- monitoring

---

Event-driven architecture 的核心优势：

## 低耦合（loose coupling）

模块不直接调用彼此。

而是：

# 通过事件通信。

因此：

系统：

- 更容易扩展
- 更容易异步化
- 更适合 distributed systems

---

# 5. State-Driven Thinking（状态驱动）

很多复杂性：

其实来自：

# 状态变化。

---

例如：

一个 AI editor：

可能存在：

- editing
- processing
- waiting
- correction available
- saving
- conflict

不同状态：

决定：

- UI behavior
- allowed operations
- backend logic

---

因此：

现代系统越来越强调：

# explicit state modeling。

因为：

很多 bug：

本质上是：

> 非法状态转换。

---

# 6. Test-Driven Design（测试驱动）

随着复杂度提高：

系统越来越无法：

“靠人工验证”。

因此：

测试逐渐从：

# 验证工具

变成：

# 设计工具。

---

TDD 的核心思想：

> 测试不仅用于发现错误，
> 还用于定义系统行为。

---

例如：

一个 dispatch policy：

真正定义它行为的：

可能不是文档。

而是：

- unit tests
- invariants
- property tests

---

复杂系统尤其需要：

# 行为级测试（behavioral testing）。

因为：

系统真正困难的是：

- edge cases
- interaction effects
- temporal behavior
- distributed consistency

---

# 7. 非功能需求（Non-Functional Requirements）

传统 Use Case：

主要描述：

# Functional Requirements。

但复杂系统真正困难的：

通常是：

# Non-Functional Requirements。

---

例如：

## Performance

- latency
- throughput
- memory usage

---

## Reliability

- fault tolerance
- retry logic
- graceful degradation

---

## Scalability

- horizontal scaling
- distributed coordination

---

## Security

- authorization
- isolation
- auditability

---

## Maintainability

- modularity
- observability
- testability

---

## UX / Human Cognition

现代系统尤其重要：

- cognitive load
- interruption cost
- feedback timing
- workflow continuity

---

因此：

优秀系统：

并不仅仅：

“功能正确”。

而是：

> 在复杂约束下，
> 仍然保持稳定、自然与可演化。

---

# 8. Feedback Loops（反馈循环）

现代 AI 系统：

越来越不是：

static systems。

而是：

# adaptive systems。

---

例如：

用户：

- 接受 correction
- 拒绝 suggestion
- 停留某些页面
- 反复犯同样错误

这些行为：

会重新影响：

- recommendation
- ranking
- model adaptation
- personalization

---

因此：

系统逐渐形成：

# continuous feedback loops。

系统：

不再只是“执行逻辑”。

而是在：

# 持续学习与调整。

---

# 9. Robustness（鲁棒性）

现实世界：

永远充满：

- uncertainty
- noise
- failure
- distribution shift
- unexpected behavior

因此：

现代复杂系统：

必须具备：

# robustness。

---

鲁棒系统：

不是：

“永不出错”。

而是：

> 在错误与不确定性下，
> 仍能维持合理行为。

---

例如：

AI system：

必须面对：

- hallucination
- ambiguous input
- adversarial prompts
- incomplete information

---

因此：

现代系统越来越强调：

- monitoring
- fallback strategies
- confidence estimation
- anomaly detection
- recovery mechanisms

---

# 10. 总结

复杂系统设计：

已经逐渐从：

# “功能工程”

演化为：

# “复杂行为系统工程”。

---

现代系统设计通常需要同时考虑：

| Layer | Focus |
|---|---|
| Business Functions | 用户目标 |
| Domain Modeling | 领域语义 |
| State Modeling | 状态变化 |
| Event Modeling | 时间与事件 |
| Architecture | 分布式与扩展性 |
| Testing | 行为验证 |
| Non-Functional Requirements | 质量属性 |
| UX/HCI | 人类认知 |
| Feedback Loops | 自适应 |
| Robustness | 不确定性处理 |

---

因此：

现代系统真正的核心，
越来越不是：

> “如何实现功能”

而是：

> “如何在复杂现实世界中，
> 设计一个能够长期稳定演化的行为系统。”
